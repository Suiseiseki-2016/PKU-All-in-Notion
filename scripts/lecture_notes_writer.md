# 讲义（讲次页）整理运行手册

> **手动触发**整理单个讲次。批量/自动模式由姊妹手册 `scripts/lecture_batch_creator.md` 负责（daily 06:00 拾起）。两本共享同一份页面规范（本文档 §4），不要写散。

## 0. 三种 mode

| mode | 触发位置 | 何处用 | 输入 |
| --- | --- | --- | --- |
| `create`（默认） | 手动 | 单讲次首次整理：从录像生成讲次页 | §1.1 四个 args |
| `overwrite` | 手动 | 已有讲次页需规范化重整（**保留 URL**，原地刷新正文） | 同上 |
| `batch` | **自动**（daily 06:00） | 扫描全部 12 门课，幂等补建缺的讲次页 | 仅 `data_root` | 

> `batch` 不在本文档实现，**改用 `lecture_batch_creator.md`**。

## 0.5 简报与失败

- 控制台回复永远是中文 4 段：**触发参数 / 创建结果 / 已落索引 / 待办**。
- 若没有 Notion MCP 工具，回 `NO_NOTION_TOOLS` 立即结束。

## 1. 触发命令

### 1.1 参数块（key=value）

```
mode=create
course_folder=计算机网络_26-27学年第1学期
course_page_id=3d791b6f-53e1-81a7-a7c1-f379bbde9086
slug=2026-09-09_2026-09-09第1-2节
data_root=E:\pku-course-data\计算机网络_26-27学年第1学期
```

- `mode` ∈ {`create`, `overwrite`}。
- `data_root` **指向课程文件夹本身**（末段就是 `course_folder`）；讲次数据在 `data_root/recordings/<slug>/` 下。macOS 手动跑时用 `…/pku-course-sync/data/<course_folder>`。
- `page_id`（可选，**仅 overwrite**）：直接指定要原地刷新的讲次页 id。早期讲次页标题可能缺 `（YYYY-MM-DD 第X-Y节）` 后缀、标题判重会失配（如《第一讲 · 计算机网络》），这种页必须靠 `page_id` 定位。

### 1.2 参数块怎么交给 droid

**Windows（主要平台）**：不要给 droid 传 stdin——ssh/PowerShell 链会弄丢 CJK。把 §1.1 参数块存成 UTF-8 文件（如 `C:\Windows\TEMP\lec_args.txt`），用仓库 runner：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File E:\remote_project\pku-course-sync\scripts\run_lecture_notes.ps1 `
  -PayloadFile C:\Windows\TEMP\lec_args.txt `
  -LogFile C:\Windows\TEMP\lec_run.out
```

runner（`scripts/run_lecture_notes.ps1`）把参数块嵌进临时提示文件、用 `-f` 交给 droid（绕开会弄丢 CJK 的 stdin 链路），并按 UTF-8 写日志。

**macOS**：命令 + stdin 直传（本机管道无跨机编码问题；若遇阻可参照 Windows runner 改用提示文件 + `-f`）：

```bash
droid exec --cwd /Users/wudi/Desktop/remote_project/pku-course-sync \
  --auto high --add-tools MCP:notion \
  -f /Users/wudi/Desktop/remote_project/pku-course-sync/scripts/lecture_notes_writer.md \
  -o text
```

然后把 §1.1 的 key=value 行送进 stdin。

## 2. 输入校验

拒绝猜测；如果下列任一项缺失/对不上，回复列出"已知 + 缺什么"给用户。

- `course_folder` 在映射表里能查到 `course_page_id`，不一致就以映射表为准；
- `data_root/recordings/<slug>/{notes.md,transcript.json,recording.json,keyframes/}` 全部存在（`data_root` 已含 `course_folder`）；
- `notes.md` 长度 ≥ 5 KB（基本可信的转写）；
- `course_page_id` 通过 `notion-fetch` 拿得到且未被归档；
- `page_id`（若给了）：`notion-fetch` 拿得到、未归档，且父页就是 `course_page_id`；
- `mode` ∈ {create, overwrite}。

## 3. 讲次号判定与目标页定位

用 `notion-fetch` 拿课程页当前子页面列表，扫一遍子页面标题，匹配正则 `《第(\d+)讲 · <课程>（YYYY-MM-DD ...）` 取最大 N；新讲次编号 = N + 1。没有任何子页时 N = 0，第一讲。（这一步只服务 `create` 的新页编号。）

目标页定位（`overwrite`，按序两条路）：
1. 参数给了 `page_id` → 直接以该页为目标；先校验它未归档、父页就是 `course_page_id`，不合格就拒绝并列出问题。
2. 没给 `page_id` → 扫子页面标题，找 `<课程>（YYYY-MM-DD 第X-Y节）` 完全一致的（日期与节次从 `slug`/`recording.json` 取）。找到 → 该页为目标；**一个都没匹配到 → 拒绝执行**，列出该课程页下讲次样式的标题清单，让用户确认或补 `page_id`，**绝不 create 新页**。

`mode=create`：若已有相同 `<课程>（YYYY-MM-DD 第X-Y节）` 标题的子页（不论 N 是什么）→ 拒绝再建第二份，回复"已有讲次页 <URL>"，**不默认覆盖**。

`mode=overwrite` → 以定位到的目标页走 §5 `notion-update-page replace_content` **原地刷新正文**：URL 不变、**原标题与讲次号 N 保持不动**、不归档不重建；原内容被替换为新规范正文。替换前先 fetch 旧正文，按 §4.4 迁移已有的 `✗` 错题标记。

## 4. 子页面规范（create / overwrite 一致）

页面标题：`《第N讲 · <课程>（YYYY-MM-DD 第X-Y节）》`。**不**设 icon。

正文按以下 5 个固定段（顺序固定）：开头段 → 大主题段 → 待核 → 自测题 → 资料来源。整体是**正常流水笔记**风格：**不**设考点速览等独立板块；考点 / 重点 / 作业考核内容在正文对应位置**加粗**（见 §4.2）。

两条贯穿全页的总原则（2026-09-16 修订，取代早先的"篇幅从紧"取向）：

- **信息完整优先于篇幅**：判据是"这节课讲过的知识点有没有漏"，不是页面长度。该长就长。
- **一条 bullet 只讲一件事**：并列概念必须拆条；例子 / 数据 / 推导 / 老师原话下沉为子 bullet。整页靠层级和体裁（代码块、表格、引用）分出视觉锚点，而不是靠平铺长句。

### 4.1 开头 1 段（80–180 字）

回答"这节课讲什么 + 跟上一讲怎么接"。**不**复述课程大纲、**不**说"本讲重点是…"这种空话、**不**开头打招呼（"大家/同学们"之类）。例（计算机网络第二讲）：

> 第二讲（9/9 周三第 1-2 节）：先以"卡车运硬盘"等案例讲当前互联网的传输、管理与治理问题（灰度失败、网络中立、GDPR），再介绍网络研究前沿（数据中心/智算网络、可编程交换机、RDMA、QUIC、DPDK/DPU），随后进入正题：网络分类与结构、传输介质、接入网、ISP 层级、路由与转发、分组交换 vs 电路交换，并以存储转发延迟计算收尾。下节课继续对比两种交换方式。

### 4.2 大主题段 `## 一、…`、`## 二、…` ……

- **数量**：3~6 个（90 分钟课通常 4~5 段；讲次 < 30 分钟可压到 2 段）。每段覆盖 ≥ 8 分钟。
- **标题格式**：`<段名>`（正常笔记风格，**不带**时间区间）。
  - 主题从 `notes.md` 抽取，**不要**用"概述 / 总结 / 举例 / 答疑"这种过程性标签。
  - **一个标题只说一件事**：`交换方式、网络服务与性能指标`这种三合一标题不合规，应拆成三段或改名为该段真正的主线。
- **bullet 数量不设上限**：每段主 bullet 8~18 条是常态，子 bullet 另计。宁可多列一条，不要合并两个知识点。
- **正文 bullet 不带时间戳**（不写 `[HH:MM]`）；每条主 bullet 讲**一个**知识点，1~2 句说完。
- **层级怎么用**：主 bullet 写结论/定义；子 bullet（缩进一级）写老师给的例子、数字、推导步骤、案例和原话。
- **老师原话优先**：结论句、易错点、辨析和考点尽量用老师自己的话，用「」括住或写成 `> ` 引用块，**不要**改写成教科书语气。paraphrase 只用于口语赘余的清理。
- **考点 / 作业 / DDL 加粗（硬性要求，不可压缩）**：以下三类内容**必须**逐条进正文（每条一个 bullet，就地**加粗**，放在所属大主题段里，不设独立板块、不重复摘抄）：
  1. **考点**：老师明示"要考 / 会考 / 必考 / 小测可能会考 / 期末会问 / 重点是 / 考试经常遇到"的内容，以及反复强调 ≥2 次的概念；
  2. **作业与考核信息**：截止日期与时间、占比、提交平台与格式要求、判分方式（自动评测/人工）、逾期与补交规则；
  3. **老师口头布置的任务**（教学网上没有的那些）：课堂上说的"下周小测""这个练习下去做""下节课要交""我后面会考大家"，含具体日期/时间的一律照抄。
  - **必须引老师原话**：这三类每条都要保留老师自己的措辞（「」或 `> ` 引用），不能只写整理后的结论。改写掉原话视为不合规。
  - **必须重读 `transcript.json`**：`notes.md` 是压缩版、会吃掉考点。写完正文后通读 transcript 全文，至少检索这些词——`会考`/`要考`/`必考`/`考大家`/`小测`/`期末`/`重点是`/`占分`/`算分`/`截止`/`交上来`/`作业`/`练习`——逐条核对是否已进正文，漏的从 transcript 原话补回。
  - **漏掉任何一条视为不合规**，哪怕整页因此变长；篇幅压缩只允许作用于普通讲解内容。
- **加粗只留给上面三类**（考点 / 作业 / DDL）。普通的定义、小标题、术语一律不加粗——整页到处加粗等于没有重点，属于不合规。
- **代码、命令、报错必须用代码块收录**（编程类课程如计算概论B 为**硬性要求**）：老师在课上演示或让大家写的完整例子（FizzBuzz、成绩分级、九九乘法表、字符串切片、函数定义等）逐个写成 ```python 代码块，能跑的形态；老师念到的报错（`SyntaxError`、`IndentationError` 等）连同触发原因一起记。**"用文字描述老师写了什么代码"视为不合规。**
- **对比 / 分类 / 多维信息用表格**：2×2（如强化与惩罚）、术语中英对照表、分类维度、参数对照、易混概念辨析，一律用 Markdown 表格，不要用平铺 bullet 硬讲。
- **公式**用行内代码或独立代码块写清楚（如 `总时延 = 传输 + 传播 + 处理 + 排队`、`动机 = 期望 × 工具性 × 效价`），不要只用文字描述。
- **术语首次出现**用中英对照（例：`文件分片 File Fragmentation`）。
- **典故 / 轶事**保留在所属大段下（"清华 SIGCOMM 11 篇"留在"中国网络研究"段），不单独立段。
- **未消解的听写错误**（如"挣占"=增长、"协议站"=协议栈、"成熟转发"=存储转发）：**第一次出现时用 [原文→修正] 注**，之后行文用修正版。
- **必须内嵌关键帧图**：每个大主题段嵌 1~3 张，全页 6~12 张，放在与内容对应的 bullet 正下方。选帧仍按内容时间就近匹配（内部参考 `notes.md` 段位 / 帧文件名自带 `XXmXXs`，从 `<data_root>/recordings/<slug>/keyframes/` 读），但 caption **不带时间**，语法 `![关键帧：<与相邻 bullet 对齐的短语>](file-upload://<id>)`，上传流程见 §5 第 5b 步。

### 4.3 `## 📌 需要自行核实的点`

bullet 列 4~10 条，含：

- 老师讲不清、看歪的小词；
- 与公开资料有出入的细节（要查，不是猜）；
- 老师的前瞻说法没学术背书的（如"光纤普及率中国第二"）；
- 跨讲次引用 / 与课程大纲冲突的（如"考查方式"）。

每条一行：「<怀疑点> <待核路径 / 建议核实来源>」。

### 4.4 `## 自测题`

每讲固定带 **3~5 题**，检验「这节课记住了什么」：

- **出题范围**：优先覆盖 §4.2 三类加粗内容（考点 > 作业考核 > 口头任务），其次是大主题段核心概念；不出纯细节题（时间点、无关数字）。
- **题型**：简答为主（「一句话说清 X 与 Y 的区别」），可配 1 道列举/填空；不出选择题——选项把答案贴在题干旁边，测不出记忆。
- **格式**：每题一个主 bullet `**Q1. <题干>**`；答案为其子 bullet，以 `答案：` 开头。自测时先不看子 bullet。
- **答案必须能在本页正文找到**：不引入正文没有的知识；写不出答案的题作废重出。
- **错题标记（用户手动）**：答错的题由用户在题干行尾追加 ` ✗`；`daily_review_mcp.md` §3.1 扫到 ✗ 会登记进「知识点与错题」库。本手册只负责出题，不写也不删 ✗。
- **overwrite 重整**：替换正文前先 fetch 旧正文，把已有 ✗ 迁移进新正文对应题目行尾；新旧题目对不上时，把带 ✗ 的旧题原样附在题目列表末尾，**不得丢失**。

### 4.5 `## 资料来源`

```
- 录像转写：<data_root_abs>/recordings/<slug>/notes.md（<MTIME>，<len> 字符，<N> 个关键段落）
- 音文对齐：同上目录 transcript.json（<duration_s> 秒，<段数> 段）
- 关键帧：同上目录 keyframes/，<computed_count> 张（按 `frame_*.jpg` 主名去重后实际数）
```

`<computed_count>` 必须自己读 keyframes 目录、按 `frame_*.jpg` 主名 dedup 出来，**不要**沿用旧的"154 张"等可能过时的值。

## 5. 落地步骤（按顺序）

1. **校验输入**（§2）。任何缺失 → 报错退出。
2. **拉课程页子页面列表**（`notion-fetch` course_page_id）→ 讲次号判定（§3）。已有同名讲次：
   - `create` → 拒绝，列原 URL 给用户。
   - `overwrite` → 走 §5.5 用 `notion-update-page` 原地刷新正文（URL 不变）。
3. **读 `notes.md` + `transcript.json`**：识别 3~6 个大主题，每段抽 8~18 条主 bullet（一条一个知识点，例子/数据/原话下沉为子 bullet，不写时间戳）。编程类课程同时把老师演示过的代码整理成代码块，对比类内容整理成表格（§4.2）。
   **随后通读 `transcript.json` 全文**，检索 `会考`/`要考`/`必考`/`考大家`/`小测`/`期末`/`重点是`/`占分`/`算分`/`截止`/`交上来`/`作业`/`练习`，把考点、作业考核信息、老师口头布置的任务逐条核对进正文（保留原话 + 加粗）；`notes.md` 漏掉的一律从 transcript 补回（§4.2 硬性要求）。
   **正文定稿后按 §4.4 出 3~5 道自测题**：优先覆盖三类加粗内容，答案必须能在本页正文找到。
4. **数 keyframes**：按 `frame_*.jpg` 主名 dedup，输出真实数量。
5. **拼页正文**：严格按 §4 结构与红线写。
5b. **嵌关键帧图**（每页 6~12 张，不可省略）：按 §4.2 选帧 → 每张调 `notion-create-file-upload`（filename 保留帧时间戳便于追溯，caption 不写时间）拿 `upload_url` + Bearer token → `curl -X POST <upload_url> -H "Authorization: Bearer <token>" -F "file=@<帧绝对路径>"`（Windows 用 `curl.exe`）→ 返回 `file-upload://<id>`，把 `![caption](file-upload://<id>)` 写进正文。注意：upload_url 约 10 分钟过期，过期就重新 create-file-upload；POST 遇 401 重建一次上传再试。
6. **建子页 / 重写正文**：
   - `create` → `notion-create-pages`，`parent.page_id = course_page_id`，properties.title = `《第N讲 · <课程>》（...)》`（N = 上一步算的）；icon 不设。
   - `overwrite` → `notion-update-page` 走 `replace_content`，新内容覆盖旧内容，**现有的 hub 子页 + 学习中心引用 URL 不变**。
7. **课堂录像笔记 hub**（`3d791b6f53e18112a603e15256c706d5`）下对应课程子页追加一行 / 覆盖一行：
   `《第N讲 · <课程>（YYYY-MM-DD 第X-Y节）》→ <url>`。
   如该课程 hub 子页暂缺，**不创建**，仅在回复里提醒"hub 没该课程子页"。
8. **学习中心**（`3d691b6f53e181d3a394f9b10e21920e`）末尾追加一行（不替换既有内容）：
   `+ 讲义整理（手动，YYYY-MM-DD）：《第N讲 · <课程>（...）》→ <url>，关键帧 X 张、资料来源：<keyframes 路径>`
9. 控制台回复：**触发参数 / 创建结果 / 已落索引 / 待办**。

## 6. 失败模式

- 没有 Notion MCP 工具 → `NO_NOTION_TOOLS` 立即结束。
- 缺参数 → 列已知 + 缺什么，等用户补，**不猜**。
- `notes.md` 不存在 / 转写未完 → 拒绝整理，返回 "等下次 daily 管道跑完"。
- hub 子页缺 → 不创建 hub 子页，仅在回复里提醒。
- `notion-create-pages` 或 `notion-update-page` 失败（网络/限流） → 不要重试 3 次，**重试 1 次**，失败就回报错误。已建好的子页保留（不在 create 失败时回滚，因为已经创建了的）。

## 7. 红线

- **不删**任何既有 Notion 页面/行/简报（overwrite 仅替换正文，原 URL 不变）。
- **必须**内嵌关键帧图（每页 6~12 张，按 §4.2 选帧、§5 第 5b 步上传）；漏嵌视为不合规。不设 cover。
- **自测题 3~5 题为硬性要求**（§4.4）；overwrite 重整不得丢失既有 `✗` 错题标记。
- **不**为了页面短而合并知识点：一条 bullet 塞两个以上知识点、把老师的代码写成文字描述、把考点/作业原话改写成书面结论，三者都视为不合规（§4.2）。
- **不**主动跑转写、不发起 schtasks、不改 `E:\pku-course-data` / `data/`。
- **不**写"待核"以外的不确定信息。
- **不**复制既有讲次页内容作为新讲次的模板（每个讲次独立写）。
- overwrite 不修改标题（URL 稳定性优先于形式改进）；改标题请先归档再 create。
