# 每日教学网晨检 · MCP 通用运行手册

你运行在 `pku-sync daily`（或 `automate`）完成之后。目标：读取本地课程状态，
与用户授权的 Notion 工作区对账，幂等登记新增作业、课件和通知，并输出中文简报。
本手册与具体 agent 宿主（Factory / Claude Code / Codex）无关。

## 工具边界

- 必须同时具有 `pku-sync` 与 `notion` 两组 MCP 工具；缺任一组就回复
  `NO_REQUIRED_MCP_TOOLS` 并结束，不要找替代方案。
- 本地课程数据只通过 pku-sync MCP 工具读取，不用 shell、浏览器或任意文件工具。
- Notion 只通过官方 notion MCP 工具读取和写入，不调用 REST，不索取 token。
- 不删除页面、数据库行或已有内容；不整页覆盖；不修改本地课程数据。

## 1. 读取本地状态

1. 调用 `health`；`ok=false` 时如实报告并结束。
2. 调用 `get_daily_status`、`list_courses`、`list_recording_status`。
3. 对每门课程调用 `list_course_files`：assignments、announcements、materials。
4. 只对需要判定的 `.md/.json` 调用 `read_course_text`，不要无差别读取全部文件。

## 2. 发现 Notion 结构

不要使用代码仓库里某位用户的固定 page/database id；每个用户的 id 都不同。

1. 搜索标题包含 `Class Notes` 且属于当前学期的 hub；无法唯一判定时停止写入，
   在报告中列出候选，请用户配置。
2. 在 hub 子树中寻找课程页及名称对应的数据库：学习任务、考核、资料索引、学习中心。
3. 每次建行前 fetch 数据源，按当前 schema 的准确字段名和选项写入。

## 3. 幂等对账

- 作业键：课程 + 标题 + 截止时间。
- 课件键：课程 + 文件名或来源路径。
- 通知键：课程 + 发布日期 + 标题。
- 录音键：课程 + 日期 + 节次。
- 先查询再创建；已有匹配项就跳过。
- 纯告知通知只进简报；含作业、考试、DDL、调课或资料更新时才登记。
- notes 已就绪但无讲次页的录音只列入“待处理”，本流程不创建讲次页。
- unavailable 录音列入“数据缺口”。

### 3.1 讲次页联动（口头任务与自测错题）

素材来源：学习中心「每日检查记录」近 7 天「讲义整理」条目里列出的讲次页 URL（正常每天只扫当天条目，漏跑的日子靠 7 天窗口兜底）。对列出的讲次页 fetch 正文，做两类登记：

- **口头任务登记**：正文里加粗的「作业与考核信息」「老师口头布置的任务」条目，凡带交件动作或日期的，登记进「学习任务」——任务名用老师原话摘要，任务类型选「作业」（小测选「小测准备」），说明 = 老师原话 + 出处讲次页链接，有日期填截止日期。幂等键：课程 + 讲次标题 + 任务摘要。纯考点加粗（无交件动作）不登记。
- **自测错题联动**：`## 自测题` 段里题干带 ` ✗` 的题，登记进「知识点与错题」数据库（先 fetch schema，按当前字段写）——标题/知识点用题干指向的概念，说明 = 题目 + 出处讲次页链接。幂等键：课程 + 题干。**不改讲次页本身**：`✗` 由用户维护，晨检只读。
- 讲次页规范（含自测题格式）见 `lecture_notes_writer.md` §4.4；本手册不复制细节。

## 4. 每日记录

在学习中心的“每日检查记录”追加当天晨检。已有当天条目时只追加复核行，
不得替换整段。无新增也写“教学网无新增”。

**每日记录的第一行固定为「管道状态」**（2026-09-16 起，用户不开终端也能看出链条断没断）：

1. 从 `get_daily_status` 的 `latest_log.content` 解析两个标记：
   `=== pku-sync daily started <stamp> ===` 与 `=== EXIT_CODE=<n> ===`。
2. 正常时写：`管道状态：daily <stamp> EXIT_CODE=0，链路正常。`
3. 以下三种情况一律以 `⚠️ 管道异常` 开头，并把日志尾部的异常行列入「待处理」段第一条：
   - `EXIT_CODE` 非 0（daily 失败；automate 保证晨检仍会运行，正是为了让这条记录存在）；
   - `latest_log` 缺失（当天根本没跑或跑在别处）；
   - `started` 戳不是今天（读到的是旧日志）。
4. 不得因为“本地管道失败”跳过晨检其余部分，也不得伪造正常状态。

## 5. 最终输出

严格分四段：同步状态 / 新增与登记 / 待处理 / 数据缺口。口头任务与自测错题登记计入「新增与登记」段；考核库出现 14 天内的已确认考试时，在「待处理」段提醒考前手动跑 `scripts/course_summary.md` 生成该课课程总结。

任何失败必须如实写明，不得假装成功。不要在输出中包含密码、token 或环境变量值。
