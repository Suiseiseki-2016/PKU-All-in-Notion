# 课程手册日期线索与按需读取验收（2026-09-29）

## 用户问题与改动

安装版已同步发展心理学两份 PDF 的目录及教学网附件指针，但没有手册文件本身。因此课程页只显示“尚未取得可读取的手册正文”，Notion 学习首页也无法突出 10 月小测、文献交付等手册日期。原“下载课程手册 PDF”入口能请求原文件，却不会把它留在应用的课程资料目录，下载后仍无法提取要求。

现在学生在课程页可主动点击“读取手册并显示要求”。应用用已有教学网账号查找新鲜附件地址，获取这一个 PDF；仅当文件名、课程目录和 `%PDF-` 文件头符合预期、体积不超过 20 MB 时，才原子缓存在该课程资料目录。随后课程页刷新，显示可提取的原文页码、日期线索和需本人参与事项。原 PDF 下载入口保留。损坏或扫描件不会让整门课程打不开，界面仍提示人工核对。Notion 学习首页从这些已读取的卡片节选原文日期及 PDF 页码，明示年份、本人参与方式和老师后续调整未核对；它们不进入正式作业截止时间列表。

## 后续网络诊断

本机 `course.pku.edu.cn` 公共首页可在约 0.09 秒返回 HTTP 200，DNS 也正常；`iaaa.pku.edu.cn/iaaa/getPublicKey.do` 直连约 20 秒报 `ConnectTimeout`。server-a 对该公共接口能返回 HTTP 200，故不是教学网全部不可达。Windows 用户系统代理启用 `127.0.0.1:7897`，但代理绕过列表明确包含 `pku.edu.cn` 和 `*.pku.edu.cn`；手工经此代理的第一次公共请求成功，随后多次出现 TLS `unexpected eof`，不能视为稳定替代线路。桌面启动层读取 Windows 代理及绕过列表；命中校园域名时向通用 Python 传递 `direct` 指令，避免其误用通用代理环境变量。通用 Python 包不读取 Windows 注册表，并会检查本地代理监听状态；当前机器因此仍使用直连。真实手册登录未再次发送账号重试，等待明确授权后才考虑一次性经 server-a 的 SSH 隧道验收。

修正代理实现位置后的完整离线回归为 **1457 项通过、1 项跳过**；Windows Rust 桌面测试 **1 项通过**，`node --check` 与 `git diff --check` 通过。当前 Rust 工具链未安装 `rustfmt`，因此 `cargo fmt --check` 未能执行；Rust 测试已实际编译桌面代码。此轮未构建安装包或执行自动更新烟测。
