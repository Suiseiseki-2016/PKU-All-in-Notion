# 按需同步与可用主链验收

2026-10-09 用户要求更新。这是开发和验收要求的更新，不是实现完成或发布通过的证明。
用户明确指出：不需要一次完成所有课程同步才能使用产品。
本文件更新同步的工作范围与验收语义；既有数据安全、真实证据和发布门禁继续有效。
历史全量九十秒失败报告保持原判定，不改写，不补填 passed。

## 产品主流程

1. 启动：显示欢迎、课程列表、左侧账号；先展示同账号已有有效缓存。
   启动和浏览不得隐式写 Notion、下载媒体或调用付费模型。
2. 进入课程：优先显示本课缓存；需要刷新时只读取本课必要的教学网元数据。
   本课讲次、作业、通知等分别区分空、未读取、读取失败及旧缓存，不用缺失替代空。
3. 单课刷新：只同步选定课程的官方元数据和对应 Notion 投影，不更新其他课程。
   状态与完成入口在界面可见；失败给出具体来源和下一步，已有内容继续可读。
4. 单讲处理：只准备选定课程/讲次及所需来源，再执行真实转写、总结和发布。
   不触发全量课程刷新，不生成所有课程总结，不让无关课程失败阻断本讲。
5. 全量刷新：是独立的后台增量任务，分课程推进；显示进度、失败项和重试入口。
   已完成的课程先可用，一门课失败不回滚或阻塞其他有效课程；允许取消和安全恢复。
   与单课任务并发时必须按账号/课程隔离写入，同课冲突明确排队或拒绝重复。

## 课程来源的自动校验

它不是学生再次选课、老师审批或人工点击确认。
教学网仍是课程身份、讲次、录像、作业及截止等官方数据的唯一权威。
账号服务用于版本一致性和多设备协调，不能替代教学网决定课程内容。

- 自动核对当前账号、稳定课程/讲次 ID、该操作所需来源的完整性及当前版本。
- 官方元数据的读取/缓存、账号版本核对、Notion 投影、总结生成分开记录状态。
  不用一个全局 complete 标记把所有课程及所有功能绑定成一次事务。
- 不相关课程的失败不阻断已验证课程；通知/作业读取失败不应无理由阻断讲次阅读。
- 共享 Notion 写入仍需有效的来源/版本、祖先/归属校验和本轮写入许可。
  若现有服务只能授权完整课程快照，应先报告确切契约限制；不得绕过许可或伪造版本。
- 不能确认某来源时，保留旧内容可读，不以旧快照覆盖新目录、不新增伪官方内容。
  涉及该来源的生成/发布说明实际阻塞原因；禁止用另一课程或手填来源冒充原测试通过。
- 不得只凭本地摘要相同跳过远端必要校验；未知写入不得盲目重放。
- UI 不直接暴露 account_unconfirmed / revision 等内部术语。
  具体区分教学网读取失败、账号目录版本冲突、Notion 授权问题和任务进行中。
  “已生成总结”只能用于本轮确实生成成功；复用旧总结明确显示复用，不能混淆。

## 按实际使用流程验收

保留 Windows 六旅程、十二个 live/fault 运行项及现有关键风险覆盖。
在既有 runner/driver/reporter 中调整相关断言和故障入口，不再新增成套零散驱动。
实施时记录旧条件→新条件→对应风险的映射，并用真实反例证明新的守卫会失败。
不得删除风险覆盖、skip、xfail、伪造证据、套用历史候选或增加强制通过入口。

- JOURNEY-02：从课程列表进入一门课、按课刷新、逐源比较讲次和中心内容；
  另一门未完整课程保持只读但不阻断目标课；后台全量任务可以部分完成、取消和恢复。
- JOURNEY-03：从选定讲次完成来源核对、真实短音频转写、合格总结、Notion 发布及回读；
  下载正确原录像、重试复用、一次结算和临时 OSS 音频清理继续验收。
- JOURNEY-05：复用该真实验收总结，生成选择/填空/问答，在 Notion 作答、批改、查看；
  保留来源冻结、答案隔离、编辑后重批改确认、历史保留和一次结算检查。
- JOURNEY-06：在实际单课/单讲入口测双击、网络故障、响应丢失、取消及崩溃恢复；
  同时测后台全量同步时前台缓存仍可浏览、有效单课可用、错误隔离和进度可见。
- JOURNEY-01/04：登录、账号隔离、安装恢复、作业准备/预览/未确认禁止提交等要求不变。

原 90 秒单课操作界限保留；不能只是将旧全量测试延长来让它变绿。
全量后台任务不再要求所有课程/讲次在这同一个 90 秒窗口内完成。
改验其可见启动与进度、前台可用、分课结果、限流遵循、有限重试、取消/恢复和安全收尾。
后台任务必须最终报告每课结果；网络请求和重试仍有上限，禁止无限运行掩盖失败。
历史全量耗时继续单独报告；后台化和部分完成不能冒充已完成全部课程同步。
断言所需超时或覆盖指纹变更必须作为此需求更新明确记录，失败证据保持不可变。

## 实施次序与完成标准

先完成一个真实闭环：打开→选课→选讲→转写→合格总结→Notion 回读→小测→作答→批改。
优先复用现有按课程入口和已验证单课能力，不先重构整个系统或优化全量树扫描。
只修复主链真实失败及既定发布门禁缺口；主链稳定后冻结候选并跑十二项完整验收。
报告三项独立计数：主链、当前候选完整运行、专项/开发检查；不能相互替代。
尚缺真实账号/邮箱或服务授权时明确提出一次具体资源请求，继续不依赖它的工作。

全部测试和媒体在 Windows，不传回 Mac；仅使用已授权账号额度，不充值。
